**Decided NOT to fix** — hall staleness fixed-timeout backstop
(`is_stale_at_speed` returns early at vel<1.0): OR-ing with a fixed 100 ms
timeout is **dangerous** — a stationary rotor legitimately produces no edges,
the backstop would declare the halls stale at every stop ⇒ `hall_sample=None`
⇒ fallback ⇒ open-loop override of 52 rad/s at a traffic light. A sensor that
died while parked is fundamentally indistinguishable from a stationary rotor
by edges alone; a broken cable is caught by the invalid-state path
(pull-up ⇒ 0b111), and the speed-adaptive path covers motion. The current
implementation is correct by design.

### HIGH

- **g431+f405: legacy `SetMode(Stopped)` on link loss cancels the
  ControlledStop failsafe.** `g431/protocol.rs:215-219`,
  `f405/protocol/servers.rs:185-189`: on link-down the state_monitor sends a
  best-effort Stopped ("authoritative failsafe is link_active" — a comment
  from the hard-stop era). Scenario on the board: the remote dies → the
  deadman (150 ms) arms ControlledStop → the board brakes → 1 s later
  transport-liveness drops the link → the state_monitor puts Stopped into
  CMD_CHANNEL → the ISR applies it: `set_mode(Stopped)` **resets
  failsafe_ctrl AND the latch** → PWM off, the board goes into a coast at
  speed. The latch is dead too: the device itself cleared it, not the host's
  "throttle to neutral". g474 is clean (sends only
  set_link_inactive). Fix: remove try_send on both boards — the link_active
  ISR gate is self-sufficient.
- **`FailsafeConfig::is_sane` lets `brake_current_a = 0` through →
  RampDown hangs forever with the last current.** `failsafe.rs:209-221`:
  `slew = (0 / ramp_s)·dt = 0`, `ramp_toward` does not move iq, the exit
  condition `iq.abs() <= max(slew,1e-3)` never triggers ⇒ the failsafe
  forever outputs `Drive{last iq}` — exactly what it is supposed to protect
  against. Nothing can deactivate it: the deadman is suppressed
  (`is_active`), the link gate is idempotent. Requires the host to write a
  broken config (0 passes `>= 0.0`). Fix: `brake_current_a > 0.0` in is_sane
  + (as a belt) a timeout on RampDown; plus a `current_iq.is_finite()`
  guard in `arm()` (NaN loops the same way).

### MEDIUM

- **Fault stop and Err from `step()` do not synchronize the shared state;
  `set_error()` is dead.** `state.rs::run_foc_cycle`: the fault gate
  (514-523) and the Err branch (549-558) put the driver into Stopped, but
  `state_mutex` stays `Running(old mode)` forever: telemetry lies to the
  host, the config server's motor-running gate forever answers Busy (storage
  profile). `MotorState::Error` is never set anywhere in production code —
  the clear_error branch in process_commands is half-dead (the protection is
  carried by `any_critical()`). Fix: fault gate → `state.set_error()`,
  Err branch → `state.set_stopped()`.
- **The driver's internal overcurrent trip never reaches the fault registry.**
  `step_current_control` kills the PWM and returns Err when the dq magnitude
  is exceeded — but no fault is latched (check_current_faults only runs over
  Ok telemetry, and the per-phase threshold ≠ the dq threshold). The host
  never learns the cause, there is no Error latch, restart is allowed
  immediately. Fix: a typed StepError and OverCurrent registration in
  run_foc_cycle's Err branch.
- **`ControlMode::Brake` does not read currents.** `foc_driver.rs:660-673`:
  with the windings shorted, current really does flow (low-side ON ⇒ the
  shunts see it, the ADC keeps triggering), but the step returns
  `FocOutput::default()` — zero software overcurrent protection (only the
  HW comparators remain), the estimators are fed zeros (the observer loses
  the rotor), telemetry is blind. A board rolling downhill in Brake is
  unmonitored. Fix: read the currents (like six_step), run the αβ magnitude
  through is_overcurrent + feed update_phase real i at v=0.
- **The hall estimator does not know the initial sector until the first
  edge.** GPIO IDR sees the hall state from boot, but `update_hall_edge` is
  only called from the capture ISR ⇒ until the first edge `sample()=None`
  → fallback → **open-loop override ±52 rad/s with torque** (the Hall source
  has `angle_trustworthy=true`, iq is not gated) on every cold start of a
  sensored board, until the rotor turns far enough to produce an edge. Fix:
  seed `update_hall_edge(read_hall_idr(), now_ticks())` in init_hall (bonus:
  a broken cable (0b111) is visible immediately at boot via the
  invalid-state path).

### LOW

- `staleness_timeout_ms` has no upper bound — the host can write
  4·10⁹ ms and effectively disable the deadman while formally passing
  is_sane. Clamp (e.g. ≤ 5000 ms) in is_sane/from_stored.
- `enter_brake_ramp` while the failsafe is already active is a no-op (arm is
  idempotent): a user Brake does not update the terminal (it stays HighZ
  from the config). Behavioral cosmetics.
- `detect_server` bracketing `try_send(Stopped)` — best-effort, silently
  lost on a full channel; in an async context `send().await` is possible
  (consistent with the config server).
- g474 `control/` is commented out — the known §5.3 item (move the ISR glue
  into core before reviving it; on revival don't forget NVIC prio 0 +
  IWDG feed + break detect, which the dormant file lacks).

### Clean (read, no findings)

failsafe state machine (except is_sane above), velocity loop,
capture_timebase (the races are written up and tested), pi_controller,
current_sense, fault registry, streaming (the ISR path is lock-free, drop on

(BDTR.modify is legal — an rw register; HardFault is above all priorities),
observer/HFI (polarity, probe, seed paths are consistent),

## 2. Suspicions (bench needed)

- **F405: the ADC injected trigger fires twice per PWM period.** [agent,
  refinement] `motor.rs:61` — `CenterAlignedBothInterrupts`;
  `hardware/peripherals.rs` triggers injected off `TIM1_CH4` RISING_EDGE;
  CCR4 near the peak. In center-aligned mode CNT crosses CCR4 **twice** per
  period ⇒ two rising edges. It probably works today: the second trigger
  (~0.4 µs) lands inside the ongoing injected sequence (~2.6 µs) and is
  ignored. **Refinement to the 2026-06-10 review:** G431 on `COMPARE_OC4`→TRGO2
  is **not fundamentally immune** — OC4REF also asserts on both passes;
  both boards rely on "the second trigger lands inside an ongoing sequence".
  The robust fix (both boards, F405 first as the live one) is one
  deterministic trigger per period (on the update event, or TIM→DMA→ADC).
  Check the JEOC rate under load on F405.
- **Detection: pipeline skew in `measure_inductance`.** [agent] [new]
  `sweep.rs:336-369` pairs the current with the *previous iteration's*
  injection, but the command goes through `CMD_CHANNEL` (drained in the ISR
  + ZOH PWM), and the real command→apply→measure latency on hardware may be
  >1 iteration; all tests apply the voltage synchronously, so the skew goes
  uncaught. May systematically bias Ld/Lq. Verify with a reference
  inductor + add a test with delayed injection.

## 3. Weak spots / gaps

### Safety

- ~~Link-loss failsafe / Layer-2 deadman~~ — **done 2026-06-11** (see §0
  and safety.md: 150 ms deadman + failsafe v2 + latch + parking brake).
- **Single-sample overcurrent/voltage with no persistence filter.**
  `fault.rs:422-436` and `foc_driver.is_overcurrent` latch on a single ADC
  sample; a nuisance trip on regen/EMI = a dangerous loss of torque while
  moving. VESC/MESC use an integrating detector (see §4 VESC-3, MESC-5).
- ~~Open-loop override always `+52 rad/s`~~ — **done 2026-06-11 (3rd
  session)**, sign from the last velocity, see §0.
- **No graduated derating** — only threshold faults (see §4 VESC-4).
- ~~Pure `Hfi` without a resolved-polarity gate~~ — **done 2026-06-11 (3rd
  session)**, iq gate on `angle_trustworthy` in `step_current_control`, see §0.

### Algorithms (gap vs VESC/MESC)

- **Position loop not implemented** (velocity done 2026-06-11 —
  `foc/velocity.rs`, the cascade for position is ready; an unwrapped
  position source is needed).
- **No field weakening or MTPA.**
- **No pole-pair auto-detection or encoder offset calibration.**
- **No real overmodulation strategy:** `modulation_limit` accepts up to
  1.2, but above the linear region SVPWM simply clamps the duty (`svpwm.rs:108-113`).
- **`apply_dq` (DirectVoltage) skips dead-time compensation**
  (`controller.rs:339-367`) — and this is the mode used by HFI inductance
  detection; dead-time distortion biases the L measurement. ✔
- ~~`has_hall()` falsely reports absent until the first edge~~ — **done
  2026-06-11 (3rd session)**, structural `is_present()`, see §0.
- ~~Low-speed staleness hole~~ — **decided NOT to fix** (3rd session,
  see the breakdown in §0): a fixed-timeout backstop false-triggers on a
  legitimate standstill and leads to the open-loop override; a sensor that
  died at standstill is indistinguishable from a stationary rotor by edges,
  a broken cable is caught by the invalid-state path.

### Architecture / firmware

- **The triplicated g431/g474/f405 glue is diverging:** g474 `control/foc.rs`
  is commented out and on revival will reproduce the F405 bugs (no priority
  0, no BKIN detect, no IWDG feed). Move the ISR skeleton / state monitor /
  ADC-IRQ-enable into core before reviving g474. [agent]
- **F405: the blocking erase of the 128 KB sector (~0.5 s) freezes the
  executor.** TOCTOU is closed (see §0), the motor is guaranteed stopped by
  the Busy gate during the write, the IWDG margin is the backstop; remains
  as a known residual.
- ~~`CMD_CHANNEL.try_send` ignores the result~~ — **done 2026-06-11
  (3rd session)**, `send().await` in all servers, see §0.
- ~~TIM1 status-register RMW~~ — **done 2026-06-11 (3rd session)**,
  complement mask, see §0.
- ~~`FaultResponse` silently truncates 8 of 16~~ — **done 2026-06-11 (3rd
  session)**, `total` field, see §0.

## 4. What to borrow from each project

### VESC (`bldc`)
1. **Force-loading the observer at handover:** on openloop→sensorless and HFI-start, force `x1/x2 = λ·cos/sin(θ)` (`mcpwm_foc.c:4014-4108`) — removes current spikes at capture. Maps directly onto your dual-slot/blend.
2. **Silent HFI (v4/v5):** injection synchronous with the PWM sequence, angle computed in the interrupt via a PI + double integrator on di/dt (`foc_math.c:744`, `mcpwm_foc.c:4801-4853`).
3. **Integrating OV/UV detector** (tolerates spikes, trips on a sustained deviation, `mc_interface.c:1881-1907`) — the answer to your single-sample current fault.
4. **Graduated derating matrix:** linear limit roll-off vs T_fet/T_motor/V_bat/ERPM/duty (`update_override_limits`, `mc_interface.c:2225+`).
5. Adaptive R observer in the background (temperature compensation of resistance, `mcpwm_foc.c:4133-4146`).
6. V0_V7_INTERPOL: a second inverse Park + SVM mid-period with an extrapolated angle — smoothness at high eRPM.
7. Reconstructing a saturated shunt from the other two to extend the current range (`mcpwm_foc.c:3068-3083`).
8. Signed open-loop on sensor loss (direction = sign of the last velocity).

### MESC
1. **FW V2 — field weakening on pure saturation feedback:** an exponential d-current ramp driven by the voltage vector hitting the circle (`MESCfoc.c:1107-1127`) — no dependence on motor parameters, self-limiting. The best candidate for your first FW.
2. **Deadshort recapture:** briefly short the phases, compute the angle from V=L·di/dt of the rising current, preload the observer and the PI integrators, go straight to RUN (`MESCfoc.c:1616-1698`) — recapture of a spinning motor without phase-voltage sensing.
3. **Hall-flux startup:** online learning of per-hall-segment flux vectors, IIR blending into the observer accumulators at low speed (`MESCfoc.c:450-459`) — smooth zero-speed torque on cheap halls.
4. **Always-on blackbox:** a ring log of Vbus/Iuvw/Vdq/angle in the fastLoop, frozen around an error, streamed over CAN (`MESCfoc.c:713-732`) — invaluable for debugging faults on the bench.
5. **Dynamic fault thresholds:** Imax = 1.5× the requested current, Vmax tracks Vbus + 15% (`MESCfoc.c:1295-1312`) — catches regen spikes on a PSU.
6. Dead-time compensation by current sign (`MESCpwm.c:157-179`) + a dead-time auto-measurement mode and a built-in double-pulse test for hardware bring-up.
7. SVM-aware shunt-pair selection: Clarke from the two phases with the lowest duty (`MESCfoc.c:823-870`).

### moteus
1. **PendSV-split ISR:** prio-0 does only the critical sampling window, the rest of the loop runs in PendSV (prio 6); encoder interrupts can preempt in between (`bldc_servo.cc:446-469`). Will become relevant with the position loop.
2. **Limit-as-fault-code telemetry:** every limit that clipped the command is reported as a code without stopping — you can always see WHAT was cutting you.
3. **Back-EMF + R·i feedforward in the current loop** (`bldc_servo_control.h:809-962`) — exactly the missing W1.
4. **PLL gains from a single intuitive "Hz" parameter**, auto-limited to ¼ of the source's actual polling rate (`motor_position.h:504-516`).
5. 32.32 fixed-point position (once the position loop arrives) — resolution does not degrade with mileage.
6. Hardware trigger chain TIM→DMA→LPTIM→ADC (works around the G4 ES0430 §2.7.11 erratum) — zero software jitter.
7. GPIO readback of the phase state inside the sampling window as hardware proof that the duty did not violate the window (`bldc_servo.cc:891-897`).
8. Flux braking: dumping regen into the windings with d-current on a Vbus threshold — no brake resistor.

### ODrive
1. **Spinout detection:** cross-checking electrical vs mechanical power (`controller.cpp:434-441`) — cheap protection against commutation loss/a drifted calibration.
2. **`std::optional` data ports reset every cycle** — structural protection against stale data between loop components (`main.cpp:371-398`).
3. **Swappable `PhaseControlLaw`:** R/L measurement is just another control law with the same arm/disarm/safety machinery (`motor.cpp:18-148`).
4. Phase-delay compensation: Park at `phase + vel·(t_meas−t_ctrl)`, inverse Park at `phase + vel·(t_pwm−t_ctrl)` (`foc.cpp:100,163`).
5. Anticogging calibration with a 3600-bin map (`controller.cpp:79-103`).
6. Documented per-task timing budget (`task_times_`, MEASURE_TIME).

### ST MCSDK (B-G431B-ESC1)
1. **Staged rev-up table + SWITCH_OVER crossfade:** parameterized phases (duration/speed/current) + a virtual speed sensor with a ramped handover of authority to the observer (`revup_ctrl.c`, `mc_tasks_foc.c:633-686`) — maps directly onto your blend crossover.
2. **Variance-gating of observer reliability** (`STO_PLL_IsVarianceTight`) before trusting the sensorless speed — a complement to your readiness (flux+PLL+min speed).
3. **MC_DURATION fault:** cheap direct detection of FOC-cycle budget overrun (the loop did not fit in the PWM period → fault) (`mc_tasks_foc.c:655-658`).
4. Park/inverse-Park delay compensation using speed in dpp × a factor (fixed point, `mc_tasks_foc.c:719,740`).
